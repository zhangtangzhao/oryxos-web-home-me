# Feature Specification: Web 管理台知识库页面

**Feature Branch**: `003-kb-admin-ui`

**Created**: 2026-09-10

**Status**: Draft

**Input**: User description: "Web 管理台知识库页面 —— 管理员在浏览器中完成知识库的建库、添加文档、摄取、总览与删除，全程不经命令行；后端管理接口能力已齐备，本特性为其补齐图形界面。"

## Clarifications

### Session 2026-09-10

- Q: 管理台知识库页面以什么形态交付和访问？ → A: 服务端托管静态页——页面作为静态资源随 OryxOS 服务端分发、由现有 Web 服务托管，浏览器直达，零新增前端工具链。
- Q: 知识库删除采用什么语义？ → A: 维持物理删除——删除即移除库、文档与检索索引，不设回收站/恢复期；误删防护依赖删除前二次确认（FR-007、SC-005）。
- Q: 知识库页面是否包含试检索（检索预览）能力？ → A: 含试检索——库详情页提供查询输入，展示命中片段与得分；为此允许新增一个只读检索查询端点（复用既有检索服务的校验与审计路径），FR-008 相应放宽，仍不新造任何写路径。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 知识库总览与单库详情查看 (Priority: P1)

管理员打开管理台知识库页面，一眼看到本部署下全部知识库的运行概况：每个库的名称、描述、文档总数、就绪文档数、失败文档数、嵌入模型与最近更新时间。点击任一库进入详情视图，可以看到该库所有文档的路径、状态（待摄取/就绪/失败）、分块数、大小、摄取时间与失败原因，并能展开查看库的内容结构总览（每篇文档的标题骨架）。

**Why this priority**: 查看是其他一切管理动作的前提——管理员必须先能"看见"库与文档的状态，才能决定建库、补文档还是修复失败项；这是页面存在的最小价值，也是独立的 MVP。

**Independent Test**: 可通过"预置 2~3 个不同状态的知识库（含一个含失败文档的库），打开页面核对列表与详情信息是否完整准确"独立验证，交付"管理员无需命令行即可掌握知识库全貌"的价值。

**Acceptance Scenarios**:

1. **Given** 部署中已存在 3 个知识库（其一含失败文档），**When** 管理员打开知识库页面，**Then** 列表按行展示 3 个库，每行含名称、描述、文档总数、就绪数、失败数、嵌入模型与最近更新时间，失败数 >0 的库有可辨识的异常标识。
2. **Given** 管理员在列表中点击某一库，**When** 详情视图加载完成，**Then** 展示该库全部文档的路径、状态、分块数、大小、摄取时间；失败文档的失败原因以人话展示，且整库的内容结构总览（文档 → 标题骨架）可查看。
3. **Given** 部署中尚无任何知识库，**When** 管理员打开页面，**Then** 展示空态提示与"创建知识库"引导入口，而非空白或报错。

---

### User Story 2 - 建库到文档就绪的完整闭环 (Priority: P2)

管理员在管理台上从零完成一个知识库的启用：填写名称（与可选描述）创建库 → 向库中添加文档（直接粘贴文本并命名，或引用服务端已有文件）→ 一键触发摄取 → 看到摄取结果汇总（处理/跳过/移除/失败计数）与逐文档结果 → 回到详情视图确认文档已变为"就绪"。

**Why this priority**: 这是本特性的核心生产力场景——没有它，管理员仍必须依赖命令行建库；它依赖 US1 的页面框架，但自身是一段完整、可独立演示的价值闭环。

**Independent Test**: 可通过"在全新空部署上，仅用页面操作创建库、添加一篇文档、触发摄取并确认就绪状态"独立验证，交付"零命令行建库"的价值。

**Acceptance Scenarios**:

1. **Given** 部署中不存在名为"产品手册"的库，**When** 管理员在创建入口填写名称"产品手册"（描述选填）并提交，**Then** 创建成功，新库出现在列表中且文档数为 0。
2. **Given** 管理员已进入"产品手册"详情，**When** 粘贴一段文本、命名为 faq.md 并提交，**Then** 文档出现在文档清单中，状态为"待摄取"。
3. **Given** 库中存在待摄取文档，**When** 管理员点击"开始摄取"，**Then** 页面展示摄取汇总（处理/跳过/移除/失败计数）与逐文档结果（路径、状态、分块数），返回详情后对应文档状态更新为"就绪"。
4. **Given** 某文档摄取失败（如嵌入服务不可达），**When** 管理员查看摄取结果，**Then** 该文档标记为失败并给出可理解的原因，其余成功文档不受影响，页面提供"重新摄取"入口。

---

### User Story 3 - 删除知识库与危险操作防护 (Priority: P3)

管理员可以删除整个知识库（连同其全部文档与检索索引）。由于删除不可恢复，页面在删除前要求二次确认，明确提示影响范围（库名与文档数）。

**Why this priority**: 删除是低频但高危的运维动作，防护优先于便捷；它不阻塞前两个用户价值的交付，故排 P3。

**Independent Test**: 可通过"对预置库执行删除流程，验证二次确认、删除后列表与详情的变化"独立验证，交付"安全清理废弃库"的价值。

**Acceptance Scenarios**:

1. **Given** 管理员在某库详情中点击删除，**When** 确认弹窗出现，**Then** 弹窗明确显示库名、文档数量与"不可恢复"警示，需显式确认后才执行。
2. **Given** 管理员确认删除，**When** 操作完成，**Then** 该库从列表消失，再次访问其详情得到"库不存在"的明确提示，不留可点击的僵尸入口。
3. **Given** 管理员在确认弹窗中选择取消，**When** 弹窗关闭，**Then** 库与其文档保持原状，无任何数据变化。

---

### User Story 4 - 试检索验证检索效果 (Priority: P2)

文档摄取就绪后，管理员在库详情页的试检索框输入一个查询，立即看到该库的命中结果：每条含文档路径、命中片段与加权得分；零命中或检索不可用（如嵌入模型身份变更）时得到明确的原因提示。这样"摄取 → 就绪 → 确认可被检索到"在页面上闭环，管理员无需回到命令行验证效果。

**Why this priority**: 它是 US2 闭环的自然收尾——"就绪"不等于"可检索"，没有试检索，管理员验证效果仍需 CLI，零命令行体验存在断层；且它是只读能力，风险低。

**Independent Test**: 可通过"对预置就绪库输入已知答案的查询，核对命中片段与得分展示；输入无关查询核对零命中提示"独立验证，交付"页面上即可验证检索效果"的价值。

**Acceptance Scenarios**:

1. **Given** 某库含一篇已就绪且内容含"回收端口"的文档，**When** 管理员在试检索框输入"回收端口是多少"并提交，**Then** 展示命中列表，首条为该文档，含命中片段与加权得分。
2. **Given** 查询与库内任何文档无关，**When** 试检索返回零命中，**Then** 页面明确提示"无命中结果"而非空白或报错。
3. **Given** 库的嵌入模型身份与当前配置不一致（检索不可用），**When** 管理员执行试检索，**Then** 页面展示"嵌入模型已变更，请恢复配置或重建知识库"的原因提示，而非通用错误。

---

### Edge Cases

- 创建时名称与既有库重复 → 页面展示明确的冲突提示（点名重复的库名），不产生任何数据变化。
- 创建时名称为空、含非法字符或超长 → 表单校验拦截并提示规则，不发起请求或得到明确错误回显。
- 添加文档时既未粘贴内容也未提供文件路径（或两者均缺）→ 表单校验提示需提供其中一种来源。
- 粘贴的文档内容为空或超出现有约束的文件类型/大小 → 给出明确拒绝原因。
- 摄取过程中嵌入服务不可达 → 汇总中失败计数 >0，逐文档结果展示失败原因，页面整体不崩溃，可稍后重试。
- 嵌入模型与建库时不一致（模型身份变更）→ 库详情中可见嵌入模型身份信息；试检索时明确提示"嵌入模型已变更，请恢复配置或重建知识库"，而非通用错误。
- 管理台与后端服务断连/后端不可达 → 页面展示"服务不可达"提示与重试入口，而非白屏或无限加载。
- 对已被他人/他端删除的库执行操作（详情、摄取、删除）→ 得到"库不存在"提示并刷新列表，不误报成功。
- 列表规模增长（数十个库、单库上百篇文档）→ 列表与详情仍可流畅加载，不做无提示的静默截断。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理台 MUST 提供知识库列表视图，展示每个库的名称、描述、文档总数、就绪文档数、失败文档数、嵌入模型与最近更新时间。
- **FR-002**: 管理台 MUST 提供单库详情视图，列出该库全部文档的路径、状态（待摄取/就绪/失败）、分块数、大小、摄取时间与失败原因，并提供整库内容结构总览（文档 → 标题骨架）。
- **FR-003**: 管理台 MUST 提供创建知识库入口：名称必填、描述选填；名称重复时 MUST 展示点名冲突提示且不产生数据变化。
- **FR-004**: 管理台 MUST 支持向指定库添加文档，来源为"粘贴文本 + 指定文件名"或"引用服务端已有文件路径"二者之一；添加成功后文档处于待摄取状态。
- **FR-005**: 管理台 MUST 支持对指定库触发摄取，并展示摄取汇总（处理/跳过/移除/失败计数与耗时）及逐文档结果（路径、状态、分块数）。
- **FR-006**: 对摄取失败的文档，管理台 MUST 展示可理解的失败原因，并 MUST 提供重新摄取入口（库级重跑即可覆盖该文档）。
- **FR-007**: 管理台 MUST 支持删除知识库：删除前 MUST 二次确认并明示库名、文档数与不可恢复警示；确认后库、文档与检索索引一并移除。
- **FR-008**: 所有管理台操作 MUST 复用既有管理接口能力完成（列表/详情/建库/加文档/摄取/删除/总览），MUST NOT 引入绕过既有校验与审计的新后端特权路径；唯一例外是试检索（FR-011）所需的**只读**检索查询端点——MUST 复用既有检索服务的校验与审计路径，且不新造任何写路径。
- **FR-009**: 页面对异常与边界状态 MUST 给出明确反馈：服务不可达、库不存在、空列表、表单校验失败、操作失败原因，均以人话展示，MUST NOT 白屏、静默失败或误报成功。
- **FR-010**: 管理台页面 MUST 仅对具备管理台访问能力的使用者开放（沿用现有管理台访问控制现状），不新增独立鉴权机制。
- **FR-011**: 管理台 MUST 在库详情页提供试检索能力：输入查询后展示命中结果（文档路径、命中片段、加权得分）；零命中与检索不可用（含嵌入模型身份变更）MUST 展示明确原因。

### Key Entities *(include if feature involves data)*

- **知识库**: 部署内的检索库单元；属性含名称（唯一标识）、描述、嵌入模型身份（模型名 + 维度）、文档计数、最近更新时间。一个库包含零到多篇文档。
- **文档**: 库内的检索素材；属性含路径（库内唯一）、状态（待摄取/就绪/失败）、分块数、大小、摄取时间、失败原因。状态随摄取推进：待摄取 → 就绪，或待摄取 → 失败（可重跑回到待摄取/就绪）。
- **摄取结果**: 一次摄取动作的报告；含处理/跳过/移除/失败计数、耗时与逐文档结果列表，仅用于向管理员展示，不独立留存于页面。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 不熟悉本系统的管理员仅凭页面提示与引导，从创建知识库到至少一篇文档达到"就绪"，全程 ≤5 分钟且全程零命令行。
- **SC-002**: 管理台 100% 的管理动作经由既有管理接口完成，新增后端特权路径数为 0；同一操作经页面触发与经接口直调产生的后端审计记录一致。
- **SC-003**: 预置 30 个知识库、其中最大库含 100 篇文档的场景下，列表与单库详情页均在 2 秒内完成加载并正确展示。
- **SC-004**: 枚举全部失败场景（重名建库、空/非法表单、摄取失败、嵌入模型变更、服务不可达、库不存在），每个场景页面上均有明确中文提示，静默失败或白屏数为 0。
- **SC-005**: 100% 的删除操作经过二次确认弹窗；在确认弹窗中取消的操作对数据 0 改动。
- **SC-006**: 管理员从"文档就绪"到在页面上确认"可被检索到"（试检索命中），全程零命令行操作；试检索在就绪库上返回首条结果的耗时 ≤1 秒（30 库/单库 100 文档规模下）。

## Assumptions

- 后端管理能力（建库、列表、详情、加文档、摄取、删除、总览）已由既有管理接口齐备提供，本特性仅补前端界面；唯一新增后端能力为试检索的只读检索查询端点（已澄清，见 FR-008 例外与 FR-011），不新造任何写路径。
- 管理台页面为**服务端托管静态页**（已澄清）：静态资源随 OryxOS 服务端分发、由现有 Web 服务托管，浏览器直达管理入口；零新增前端工具链与独立前端工程，与"私有部署、数据不出域"定位一致。
- 管理台的访问控制沿用部署现状（内网/既有入口），本特性不设计新的登录与权限体系。
- 文档格式沿用现有约束（Markdown/纯文本），页面不做格式转换。
- 面向单管理员或少量管理员的低频操作场景，不做多人并发编辑冲突处理；对已被他端删除的库以"操作时报库不存在"兜底。
- 删除为物理删除（已澄清）：删除即移除库、文档记录与检索索引，不设回收站与恢复期，也不做删除前导出备份；防护依赖二次确认，页面文案按"不可恢复"提示。
